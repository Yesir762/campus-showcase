## 修正结果

1. 修正实体旋转为 **X 轴 −90°**。原 +90° 把源坐标向上的 Z 轴映射成向下的 Y 轴，导致从底面观察建筑。采用完整 LOD0 边界中心重新计算偏移 `[-1.45829483, 1.42573200, 0.76569427]`，统一缩放仍为 `0.02`。浏览器确认屋顶、树冠和建筑立面方向恢复正常。
2. 新建 `yujiatou-test-v2`，同时更新场景与空间绑定。默认使用 **Streamed SOG**，包含原始 LOD0/1/2 三档，而非固定 LOD2。先加载低精度概貌，首帧实际有高斯点渲染后再开放交互，随后按距离补充细节；当前场景点数预算为 300 万。
3. 保留固定高清、标准、轻量选项。高清资源保留全部 7,198,758 点，SOG 为 **88,233,530 字节**；标准为 44,655,391 字节，轻量为 11,496,720 字节。SOG 有量化压缩，不能称为无损，内存也不与下载大小同比下降。
4. 提供单分块对照资源。访问 `/?model-compare=1#campus-3d` 后出现 Block000 的三档选项。切换后重载，并选同一预设视角；FOV、模型变换与画布尺寸必须保持一致。对照模式运行信息显示实际相机和目标坐标，用户手动拖动后须复位再比较。
5. 导入脚本支持指定 LOD、分块及输出目录，修正合并头部范围注释，保持 PLY 数据体字节不变，并记录源数据哈希。
6. 平移范围、FOV 和点数预算移到相机配置。加入近 60 秒中位帧率和首次可交互耗时记录；连续 10 秒低于 20 FPS 时降低分辨率，再次持续较慢时提示切换轻量或退出三维。

检查已核验六个 SOG 的哈希、字节数、内部资源及点数；流式资源为 **39 个分块、235 个文件**，每档点数分别为 7,198,758 / 3,592,750 / 897,910，没有因分块丢点。`streamed-integrity.json` 提供流式文件完整性清单。

## 发布与回滚

发布时需上传整个 `public/models/yujiatou-test-v2` 目录，保持相对路径，特别是流式分块中的 `meta.json` 与 WebP 文件；仅上传顶层 `lod-meta.json` 无法渲染。大模型产物不进入普通 Git，其他机器需再生成或从模型存储获取。

使用 CDN 时，应对整个模型目录设置 CORS，启用 HTTPS、提供 Content-Length，并对版本化资源采用长期缓存。场景配置随网页构建发布，更新网页后才切换默认版本。当前无线上链接，线上 HTTP、缓存和跨域尚未验收。

回滚时将 `config/scene.json` 的 `activeVersion` 设为 `yujiatou-test-v1`，并将 `config/bindings-yujiatou-test-v1.json` 复制为 `config/bindings.json` 后构建。旧 PLY 保留不覆盖；旧版绑定备份也已应用 −90° 朝向修正，避免回滚重新倒置。

## 验收边界

已完成本地 WebGL2 实际渲染、三档资源检查、精度切换、分级加载、方向修正以及构建验证。修正方向后，在固定 1280×1200 视口、同一初始相机和渲染参数下重新检查 Block000 的 LOD2/1/0，截图记录于 `work/corrected-block0-lod*.jpg`。全景视角的建筑方向一致，近景画质仍应在对照入口使用同一细节视角进一步验收。此前错误朝向的截图不作为最终画质结论。

Chrome/Safari 实机对照、20 Mbps 网络下加载目标、运行内存峰值和十分钟稳定性尚待正式验收；本地回环网络的耗时不能替代这些结果。手机资源保持未配置，维持图文降级。外围漂浮点未按未经确认的裁剪范围自动删去，需要结合参考视频与校园地标确认后清理。

实现依据：[Streamed SOG](https://developer.playcanvas.com/user-manual/gaussian-splatting/building/lod-streaming/)、[生成分级资源](https://developer.playcanvas.com/user-manual/splat-transform/streamed-sog/)。
